# Veteran Career Path independent resume program

The source builds into /resumereview (with /resume-workspace compatibility) for Firebase Hosting and the GitHub Pages artifact that serves veterancareerpath.com. Run node scripts/build-resume-workspace.mjs and node scripts/build-hosting.mjs from the repository root. Source, tests and server libraries are not copied into the public artifact.

Free program accounts use a named Firebase app session, independent of main-site subscription access. Authentication identities share the veteran-career-builder project, so existing emails sign in/reset instead of creating a duplicate identity. Program background and saved editor data use profiles/{uid}/resumeProgram/background and profiles/{uid}/resumeProgramResumes/{id}. Existing owner-only rules apply. Do not change billing entitlements in client-writable paths.

AI builds cost $1.99 USD through the existing Stripe account. The matching server implementation lives in Phocas88/vcp-proxy api/_lib/resume-program.js, dispatched through the existing /api/claude function with workspace:true. No additional Hobby function, Stripe subscription or new webhook is required. STRIPE_SECRET_KEY and FIREBASE_SERVICE_ACCOUNT_JSON are already provisioned. OPENAI_API_KEY selects the existing OpenAI connection; ANTHROPIC_API_KEY remains a fallback for deployments configured for Anthropic. Both providers are disclosed where used. All keys remain server-side.

Private build records live under _privateResumeProgramUsers/{uid}/builds/{hash}, excluded from client access by existing default-deny rules. Checkout requires explicit recovery-storage agreement. The server binds input/context to owner, sets the price, verifies payment with Stripe directly, serializes executions with a lease, saves successful results and leaves failed builds retryable. Returning or refreshing never needs a second payment for that build. Purchase history can reopen/delete build input and result; minimal accounting records remain.

Structured military fields mirror the full app's service schema, including MOS roles, clearance opt-in/status, identifiers, additional duties, awards and deployments. Civilian jobs, education, certificates, training, skills, languages and projects are repeatable structured entries. Facts and credential status are never inferred. Legacy saved drafts remain readable.

Privacy, cookies and one-time purchase terms are in public/privacy.html, public/cookies.html and public/terms.html, with matching company policy supplements. Functional verification uses fictional data and fake payment/provider responses; real card payments are never made by tests.

Branch choices now match app.html/app.js catalogs: branch-specific ranks/pay grades, searchable specialties, ASI/NEC/AFSC qualifiers, SQI/warfare designators and awards, plus common additional-duty options. The static catalog preserves the company tables, with manual fields for historical/unlisted entries. Changing branches asks before clearing incompatible selections. Sample UI and sample results were removed. The $1.99 / resume build banner leads the page; checkout unlocks the builder before resume entry, while purchase recovery stays available.

First visits offer a free account or guest access and explain saved resume/background benefits. One guided stage is shown at a time: start, upfront checkout, background or import, text check, job details, then AI review. My resumes contains saved versions, explicit background saving, optional submitted-draft snapshots, and purchase history. No automatic cloud saving occurs.

Guest checkout uses the existing backend guest action to mint a rate-limited custom Firebase session. Creating a new email/password account links the same UID and retains its purchases. Existing-account sign-in does not transfer guest purchases. Guest access lasts for the browser session; downloading or creating an account is recommended before leaving. Verified Stripe returns automatically run or reopen the build. Tests cover the account/guest flow, ownership isolation, consent, recovery, branch fields and readable templates.

Career tools adds a reusable profile editor, application tracker, named resume snapshot families, job-requirement evidence, military skills translations and cover-letter editing/PDF/Word/text export. The navigation stays horizontal on desktop and wraps on mobile. Optional account saves use the existing owner-only `profiles/{uid}` rules: `resumeProgram/background`, `resumeProgramResumes/{id}`, `resumeProgramJobs/{id}` and `resumeProgramLetters/{buildId}`. No Firestore rule or index migration is required; lists order by one timestamp and load the most recent 50 resume versions / 100 jobs / 100 letters. Account export includes those lists. Delete controls remove individual active records; purchase-data deletion also removes the generated kit.

Each completed purchase includes one server-cached AI career kit per result revision via the existing `workspace:true, action:career` endpoint. It uses the stored applicant input and verified clarification details, never arbitrary client prompts. The server re-verifies Stripe (including free coupons), enforces owner access/quota/a lease, streams whitespace heartbeats, saves successful output and retains retry rights on failure. Requirement and skill evidence must quote submitted facts. Numeric additions in cover letters are withheld; the user must still check semantic accuracy. A clarification revision allows a fresh kit; choosing another job requires a new confirmed build. The existing review performs the full resume tailoring.

Application-to-checkout handoff stores a private source snapshot and job only after storage consent. The purchase keeps opaque saved-item references, and restores those owner-scoped items after payment. Resume content is not sent to Stripe. Versions retain the original build reference so reopening a linked purchase does not charge again. Older versions lacking a purchase reference require reopening the original purchase manually. Guests may use included career kits; permanent profile, tracker, version and edited-letter saves need a free account. Nothing automatically applies to jobs, contacts recruiters or sends date notifications.

Validation: `npm run check` covers model/privacy scope and UI controls; backend `npm test` covers entitlement, ownership, caching, race/retry, deletion and AI output guards. Browser tests: `e2e/career.spec.mjs` uses fictional accounts/payment/provider fixtures, exercises profile saves, application linking, version compare/restore, AI-kit rendering and real PDF/Word exports. No real charge is created by tests.

The free Service library is a lazy-loaded in-app browser for MOS/rating/AFSC/SFSC, ASI/NEC/branch qualifications and special designators across all six branches. `scripts/build-service-library.mjs` regenerates its JSON from the website catalogs (`app-data.js`, `vcp-mos-data.js`, `vcp-military-data.js`), researched `data/mos-curation.json`, O*NET crosswalk data and existing guide paths on each root workspace build. Generated JSON is ignored by git but included in both published resume paths. Search, branch/type filters, 20-item pagination, source details and civilian paths are local browser functions with no AI charge or new tracking. Military O*NET occupation codes are not described as civilian options.

Conflicting labels for the same branch/type/code remain separate and visibly marked. Adding an entry requires explicit confirmation that the user held it, an editable verified description, and a matching or new service experience. Only the selected code/title is copied into the draft profile; generic duties, achievements, qualifications, dates and career recommendations are never imported as user facts. Cloud saving remains a separate explicit consent/Save action. Unlisted/historical entries retain manual entry. Prepare / Organize / Improve group the tool navigation; completed AI-kit controls collapse so results are easier to reach.

Service-profile setup now follows branch/rank/dates, MOS/specialty, additional qualifiers, then duties/results. Each service experience may include dated rank history and independent primary/current rank, base specialty, full recorded code (for example 88M02), and an optional explicitly supplied skill level. Full codes are never constructed from rank and no SQI/ASI is inferred from a suffix. Known full Army codes can look up their base specialty title without decoding qualifiers. Existing full Army codes in older single-code profiles are retained in the full-code field on load. Rank and grade choices in a historical entry are independent of current rank. Branch changes ask before clearing incompatible branch-specific values and preserve history dates/duties.

All new fields and history normalize with the saved profile and feed the starting resume draft, so the paid AI process receives the user’s actual recorded information. Existing profiles remain readable. Library additions preserve compatible full codes; selecting a different specialty clears incompatible full-code/skill details after confirmation. New service-profile unit and browser tests exercise exact full-code preservation, multiple branches, history, qualifiers, profile save/load and paid draft generation.

## Standalone app navigation

VCP Resume is an independent app by Veteran Career Path. The Home screen starts or resumes work. Persistent horizontal navigation opens Resumes, Profile, Applications and Library as full screens; review and downloads stay within the selected resume workflow. Settings contains legal, storage, account and purchase-recovery controls. The main website marketing navigation and footer are not used in the app.

The profile editor shows one category at a time while retaining all entered categories and branch-specific controls. Profile edits and library selections stay in memory unless the user explicitly saves them with account-storage consent. The existing independent Firebase session, data collections, upfront $1.99 payment and purchase recovery are unchanged.

Run `npm run test:career-browser` for navigation, narrow-screen layout, profile persistence, purchase guards, library, application tracking and resume-version checks.

## Guided profile setup

After creating or linking a new app account, users are guided through the nine profile sections with specific prompts, optional tips, Back, Skip and Finish later. The section picker still works. Skipping never clears existing facts and finishing the walkthrough does not buy or generate a resume. Existing users and guests can start the walkthrough from Profile.

Private guided saving is off by default. With explicit opt-in, Next, Skip and Finish later save the current profile and bounded setup metadata together in the owner’s existing `resumeProgram/background` document. Home offers to resume an unfinished setup after sign-in; loading it confirms before replacing unsaved fields. Without saving, progress stays in the current tab. Account changes clear the guide and pending responses are discarded.

## Resume design studio

The studio provides 24 original templates, including three guarded federal presets. Templates, formatting and section editing are included in the existing build price. Choose Templates, Formatting or Sections; preview the generated PDF before downloading. Supported controls include three self-hosted font families, body/name/heading sizes, spacing, margins, color, alignment, US Letter/A4, custom headings and section order, reversible exclusions, custom sections, manual text editing and optional photos in selected civilian layouts. Save a version to preserve settings; device drafts remain opt-in.

All formatted outputs derive from the same parsed document model. PDF embeds its fonts and provides the authoritative page preview. Word and browser-print pagination may vary; verify them before submission. User-controlled section exclusions affect downloads but retain the source for restoration. Nothing is cut automatically to meet a page limit. Two-column templates put supporting sections in their side column; prefer simple templates for online applications.

Federal defaults follow current USAJOBS/OPM guidance, checked October 24, 2026: single column, sans-serif body at least 10 pt, headings at least 14 pt, half-inch minimum margins, US Letter, no photo, PDF up to 5 MB and a two-page limit. The file-size and page guards run before PDF/Word downloads and the app Print button; Word's actual pagination still requires a separate check. Required information is checked per relevant job (employer, month/year dates, hours/week); education, credentials and supporting documents depend on the announcement. A template does not establish eligibility or agency acceptance. NIST's specific restriction on AI-generated resume text is surfaced when its name appears in an announcement.

Primary sources:
- https://usajobshelp.opm.gov/hc/en-us/articles/52839989720851-How-do-I-write-a-resume-for-a-federal-job (updated October 21, 2026)
- https://www.opm.gov/policy-data-oversight/hiring-information/merit-hiring-plan-resources/applicant-guidance-on-the-two-page-resume-limit/
- https://www.nist.gov/careers/application-tips/section-5-what-not-include-your-application

Competitor screenshots supplied by the user showed template browsing, font/color/spacing controls, headings/order, margins, paper sizes, preview and print. These are covered by the studio. The existing veteran differentiators remain branch-aware career profiles and qualification libraries, factual AI editing, job matching, cover letters, private saved versions and application tracking. These observed capabilities are the comparison scope; no unsupported claim of universal competitor or ATS superiority is made.

Validation includes actual PDFs from all 24 templates, Word text in each layout family, source-fact preservation, reversible exclusions, saved design restoration, photo handling, overlength federal guards, and multi-page browser print. Font files and their OFL licenses are packaged locally from pinned Fontsource packages; browser formatting never fetches third-party fonts or sends optional photos to the AI service.

## Google sign-in

Continue with Google is available on Welcome and Account. Firebase Google authentication is already enabled and the production domain is authorized (public configuration and provider handshake checked). The program keeps its named Firebase auth instance and private data namespaces. Only Google basic identity scopes are requested; no Gmail or Drive access, photo import or extra subscription is added. SDK and session persistence are prepared before enabling the button so the popup opens directly from a user gesture, including on mobile. Redirect fallback is deliberately avoided because cross-origin redirect auth can fail when browsers partition third-party storage, and redirecting unsaved guest work would be unsafe.

Guests link the Google credential to their existing Firebase UID, preserving purchases and current work. A credential collision does not sign out or merge the guest; switching to an existing Google account requires explicit confirmation of possible lost guest access. Existing email users can link Google from Account after signing in with their existing method. Provider credentials are not retained in app storage or logs. New Google accounts and converted guests enter guided profile setup; existing accounts do not restart it.

Session persistence is the default. Longer-lived account storage requires Keep me signed in. Guest identities remain session-only if Google linking fails or is cancelled. Cancellation, popup blocking, unsupported browsers, provider/domain configuration and different-credential conflicts have specific recovery messages. In-app browsers may require opening Chrome/Safari; users are told to save/download guest work before changing browsers.

References: https://firebase.google.com/docs/auth/web/google-signin and https://firebase.google.com/docs/auth/web/redirect-best-practices (popup alternative).
